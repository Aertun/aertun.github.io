Connectors

A connector reads one tool through its API, over only the endpoints its manifest declares, with a credential sealed under Aertun's keyring. With no keyring, no credential can be stored.

aertun vault enable
aertun connect catalogue
aertun connect add okta --org example
aertun connect check okta
AERTUN_CONNECT_SECRET=... aertun connect secret okta
aertun connect run okta --save

A region is chosen from the connector's own list, never typed as a hostname, so adding a connector cannot point a credential at another machine. The catalogue says which credential each needs and the least it should be allowed to do.

Shipped connectors: Okta, Microsoft Entra ID, GitHub, EVM smart contracts through a Blockscout explorer, KnowBe4, ManageEngine Endpoint Central, ManageEngine MDM Plus and Vanta. aertun connect probe shows the shape of a response, never its values.

Collection

aertun collect run
aertun collect file aws/cloudtrail trail.json
aertun collect auto 15m

Logs are mapped to one shape from AWS CloudTrail, Microsoft Entra ID, Microsoft Azure, Google Workspace, Google Cloud, Okta, Duo, CrowdStrike Falcon, Jamf Pro, GitHub, Kubernetes, Cloudflare, Salesforce, Slack, Snowflake, Wazuh, Linux auditd, EVM chains, the OpenAI and Anthropic audit logs, LiteLLM, and GenAI agent telemetry over OTLP. aertun source add adds a mapping of your own, checked against a sample, and aertun telemetry check says whether what it produces can be used at all.

Feeds pushed to Aertun

aertun inbound add ssf corp-idp --issuer https://acme.okta.com --url https://aertun.example.com --alias okta
aertun inbound add okta okta-hooks
aertun inbound add webhook github --mapping github/audit --github
aertun inbound add webhook billing --mapping billing/admin
aertun inbound add webhook litellm --mapping litellm/requests --bearer
aertun inbound add webhook wazuh --mapping wazuh/alerts --seal
aertun inbound add stream site-b --keys site-b.keys.json
aertun inbound status NAME

A feed's endpoint is /feeds/NAME on the console. Shared Signals (SSF, CAEP, RISC) are verified against the transmitter's keys; a webhook against its signing secret, as Standard Webhooks or GitHub sign; a sender that can set a header and cannot sign, with --bearer, against a static secret in Authorization, which proves who sent a delivery and not that its body is the one sent, so give its address only over https. Every webhook's records go through a mapping (--mapping ISSUER/STREAM, from aertun source list). With --seal, each record's digest is also committed to the audit log within 30 seconds of arrival, in one entry for each batch, so proof sealed can later show it existed by then. A stream feed takes another deployment's signed audit log (peer log). What arrives is stored like anything collected, and put to the automations as a signal.

LiteLLM

aertun inbound add webhook litellm --mapping litellm/requests --bearer

A LiteLLM proxy is the gateway most agents call models through, and it knows whose key each call came on. Point its generic_api logging callback at the feed's URL with the Authorization header the command prints; each call arrives as a litellm/requests event whose actor is the virtual key, by its hash, with its alias and team beside it. What was asked and answered is never read. Its OpenTelemetry traces can go to Aertun's OTLP endpoint as well (/v1/traces, protobuf or JSON). An agent's own account can then be held against the gateway's record: aertun agent reconcile NAME --gateway litellm/requests:KEY.

Wazuh

aertun inbound add webhook wazuh --mapping wazuh/alerts --seal

Wazuh's alerts arrive through custom-aertun.py, which the manager's integrator runs for each alert and which signs it as a Standard Webhooks delivery. Each is stored as a wazuh/alerts detection and sealed. In the other direction, a Wazuh agent tails Aertun's audit log and aertun_rules.xml raises alerts on the kill switch, refuted proofs, forked peer logs, refusals, privilege and legal holds. The script, the rules, their tests and the steps are in the repository's integrations/wazuh, tested against a Wazuh 4.14.10 manager. aertun mdr can then test the Wazuh deployment itself, blind.
