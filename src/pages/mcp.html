The agent interface speaks MCP over standard input and output, and over streamable HTTP at /mcp beside the console, where an agent authenticates with OAuth 2.1 (PKCE, and DPoP-bound tokens) or a token. It acts as the person or agent whose credential it carries, with that access and no more. An agent loads only the operations it searches for with aertun_find.

OperationWhat it does
list_findingsthe finding queue, most urgent first
read_findingone finding: why it ranks, its evidence, and what has been decided
propose_finding_decisionsuggest a decision on a finding for a person to make — the one write
list_proofsthe proofs kept here: proven, refuted or inconclusive, and whose key signed each
read_proofone kept proof: its claim, checks, evidence and materials
verify_proofcheck a signed proof against its public key, and whether this store trusts that key
list_claimsthe claim cards registered, and when each window closes
incident_statusopen incidents: which clocks are running, late or not started
detection_statswhat each rule has been worth, and what the numbers suggest changing
vuln_planthe smallest upgrades that clear the most vulnerability risk
estate_summaryhow many people are at each level of risk, as numbers, never names
findfind a screen by words

Every value an operation answers carries attacker_writable: whether somebody outside Aertun could have written it — a finding's title, a rule's name, a log's text. An agent reading events is reading text an attacker chose, so nothing on this interface changes who may do what, approves anything, signs or keeps a proof, or reaches another platform. A refusal is the answer, with the reason, and is recorded like every call.

The same answers twice

aertun twin record --out case.twin.json
aertun mcp --twin case.twin.json

A recorded case answers from one file under its digest: the same bytes every time, proposals refused, and a file that no longer matches its digest refused outright — for putting the same investigation to an agent, or two agents, more than once.
