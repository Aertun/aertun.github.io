A proof of this kind is an in-toto Statement v1 in a DSSE envelope whose predicateType is this page's address. Every kind is described on Proofs.

What it claims

Each setting a posture file declares — a Safe multisig's threshold and owners, a timelock's delay, a proxy's admin and implementation — is at least what it declares, read from the chain at one block named by its hash.

Its verdict

refuted when a setting is weaker than declared, each named by contract, setting, declared and found; proven when every setting was read and holds; inconclusive when one could not be read, saying why. The endpoint’s address is never written into the proof.

aertun chain posture protocol.posture.json --rpc https://rpc.example --key signing.key --out posture.proof.json

What every proof carries

FieldHolds
verdictproven, refuted or inconclusive
claimthe sentence that was checked, in words
authorwho made the work under test, where that is known: {"by","model","prompt_sha256"} — a digest of the prompt, never the prompt
verifierwhat checked it: {"id","version","program"}
materialsevery input the verifier read besides the subject, each as {"name","digest","entries"}
checkseach check as {"name","passed","detail","failures"}: what it found, and each failure named
chain_posturethe evidence below, which is set only on this kind
verified_atwhen the verifier ran, UTC, RFC 3339

The evidence: predicate.chain_posture

ChainPostureEvidence is what a chain-posture proof rests on.

FieldTypeMeans
namestringName is the protocol's name as the posture file gives it: lower-case letters, digits, '.', '_' and '-', at most 64.
chain_idint64ChainID is the chain the posture file declares, and the one the endpoint said it serves.
blockint64Block is the number of the block every setting was read at.
block_hashstringBlockHash is that block's hash. Every read named the block by it (EIP-1898), so every setting was read from the same state.
finalizedboolFinalized says the block was the endpoint's latest finalized one, read at because the operator named no block.
settings[]PostureSettingSettings are every setting the posture file declares, in its order, with what was read for each.
heldintHeld is how many settings were read and hold.
regressedintRegressed is how many settings were read and do not hold.
unreadintUnread is how many settings could not be read.

Generated from the program's own definition of this predicate, so these are the names a proof carries.

Verifying one

aertun proof verify --key proof-key.json PROOF.json                 # both signatures, and the verdict
python3 scripts/verifyproof/verify.py PROOF.json proof-key.json     # without Aertun

Both signatures are over DSSE's pre-authentication encoding of the payload: Ed25519 as DSSE defines it, and ML-DSA-65 (FIPS 204) in the context aertun/proof/v1. A signature says which key signed, never whose; whether to trust the key is yours to decide, and a store's trusted signers say whose it is there. Nothing an author wrote is copied into a proof beyond identifiers and numbers that passed a strict parser.
