A proof of this kind is an in-toto Statement v1 in a DSSE envelope whose predicateType is this page's address. Every kind is described on Proofs.

What it claims

Every not_affected statement a party made about one asset holds against Aertun's bill of materials, advisories and reachability analysis for that asset.

Its verdict

refuted when any statement is contradicted, each named; proven when every statement is supported; inconclusive otherwise, with the reasons statements could not be checked counted.

aertun vuln prove-vex vendor.vex.json --source NAME --where ASSET --key signing.key --out vex.proof.json

What every proof carries

FieldHolds
verdictproven, refuted or inconclusive
claimthe sentence that was checked, in words
authorwho made the work under test, where that is known: {"by","model","prompt_sha256"} — a digest of the prompt, never the prompt
verifierwhat checked it: {"id","version","program"}
materialsevery input the verifier read besides the subject, each as {"name","digest","entries"}
checkseach check as {"name","passed","detail","failures"}: what it found, and each failure named
not_affectedthe evidence below, which is set only on this kind
verified_atwhen the verifier ran, UTC, RFC 3339

The evidence: predicate.not_affected

NotAffectedEvidence is what the statements came to, as counts.

FieldTypeMeans
sourcestringSource is the operator's short name for whoever wrote the document; Asset the asset it is about, as its bill was imported under.
assetstring
statementsintStatements is every statement the document made, NotAffected those tested, and Checked the statement-and-package pairs they came to.
not_affectedint
checkedint
supportedint
contradictedint
uncheckableint
reasons[]ReasonCount

Generated from the program's own definition of this predicate, so these are the names a proof carries.

Verifying one

aertun proof verify --key proof-key.json PROOF.json                 # both signatures, and the verdict
python3 scripts/verifyproof/verify.py PROOF.json proof-key.json     # without Aertun

Both signatures are over DSSE's pre-authentication encoding of the payload: Ed25519 as DSSE defines it, and ML-DSA-65 (FIPS 204) in the context aertun/proof/v1. A signature says which key signed, never whose; whether to trust the key is yours to decide, and a store's trusted signers say whose it is there. Nothing an author wrote is copied into a proof beyond identifiers and numbers that passed a strict parser.
